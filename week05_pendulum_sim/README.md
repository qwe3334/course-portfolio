# 人机协同三反思

## 1. 意图设计思考

【思考手记】：在编写初始 Prompt 时，我采用了"四段式"结构（角色-目标-约束-输出），特意设置了三层约束边界：

**技术约束**："单文件 index.html，不依赖外部库"——这避免了 CDN 网络加载失败的问题，确保双击就能在浏览器跑通 MVP。我还指定了 Canvas 尺寸 700×560、暗色主题 `#1a1a24`、发光摆球效果，这些具体的视觉参数让 AI 不需要猜测我的审美偏好。

**物理约束**：我明确要求"使用 RK4 数值积分"而非简单的欧拉法，并指定了初始角度 120°、重力加速度 9.8、摆长 140px。这些参数来自课堂讲义，确保仿真结果具有物理真实性，而不是随意的动画演示。

**交互约束**：我要求"支持鼠标拖拽摆球设定初始角度"和"实时显示能量、角度、时间"，这些功能让仿真从"被动观看"变成"主动探索"，符合建构主义学习理念。

**关键洞察**：Prompt 的质量决定了 AI 输出的上限。我花在定义约束上的 10 分钟，节省了后续 2 小时的反复修改。AI 擅长在明确边界内填充细节，但边界本身必须由人类定义。

## 2. 报错自愈思考

【思考手记】：整个开发过程中遇到了两个关键报错，我通过"客观证据 + 精准描述"的方式引导 AI 快速修复：

**报错 1：ReferenceError - resetAnimation is not defined**
- **现象**：点击"重置"按钮时控制台报 `ReferenceError: resetAnimation is not defined at HTMLButtonElement.onclick`
- **我的操作**：我把完整的报错信息、行号、以及"按钮使用了 `onclick="resetAnimation()"` 但函数未定义"这个关键线索发给 AI
- **AI 响应**：2 秒内定位到问题是变量作用域冲突，修复为使用 `addEventListener` 而非内联事件处理器
- **反思**：如果我只能说"重置按钮坏了"，AI 需要花时间猜测问题所在。但提供具体的报错信息，就像给医生看化验单，诊断速度提升了 10 倍

**报错 2：RK4 能量漂移 15.3%（最关键的 debug）**
- **现象**：仿真运行 8 秒后，总能量从 20581 J 漂移到 25017 J，增加了 21%
- **我的操作**：我没有说"能量守恒不对"，而是提供了定量证据："dt=0.001 时漂移 15.3030%，dt=0.002 时漂移仍然是 15.3030%，dt=0.008 时还是 15.3030%"
- **AI 的突破**：这个"漂移与时间步长无关"的关键证据让 AI 意识到问题不在数值精度，而在物理方程本身。AI 随后推导出标准双摆方程，发现代码中有两处错误：
  1. 分母缺少因子 2：`2*M - m2*cos²Δ` 应为 `2*M - 2*m2*cos²Δ`
  2. 第一项质量系数错误：`2*M` 应为 `2*m1 + m2`
- **修复后**：能量漂移从 15.3% 降至 0.000000%，30 秒仿真完美守恒
- **反思**：这次 debug 教会我"定量证据 > 定性描述"。如果我只说"能量不守恒"，AI 可能会盲目调整时间步长或尝试辛积分器。但"漂移与 dt 无关"这个反直觉的事实，直接排除了数值误差的可能性，将问题定位到物理建模层面

## 3. 人机协同哲学反思

【思考手记】：在这场创造中，AI 与我各自承担了不可替代的角色，形成了"人类定义问题空间 + AI 探索解空间"的协同模式：

**我的核心价值（人类不可替代）**：
1. **意图定义者**：我决定了"要做什么"——双摆混沌仿真而非单摆、暗色主题而非亮色、120°初始角度而非 45°。这些选择来自我的审美判断、教学目标和物理直觉
2. **质量验收者**：AI 生成代码后，我通过浏览器运行、观察动画、检查能量守恒来验证结果是否符合预期。AI 无法自己判断"这个动画看起来是否自然"
3. **证据提供者**：在 debug 能量漂移时，是我通过多次实验发现"漂移与时间步长无关"这个关键线索，为 AI 提供了突破方向
4. **伦理把关者**：我确保代码包含学号、姓名等课程要求信息，确保仿真用于教育目的

**AI 的核心价值（机器不可替代）**：
1. **语法知识库**：AI 瞬间调用了 Canvas API、RK4 算法、拉格朗日力学方程等知识，而我需要查阅讲义和文档
2. **代码生成速度**：AI 在 2 秒内生成 300 行可运行的代码，而我手动编写需要 3 小时
3. **数学推导能力**：在修复能量漂移时，AI 从拉格朗日量出发，完整推导了双摆运动方程，并与 Wikipedia 标准形式对比验证。这种符号推理能力远超我的手工计算速度
4. **模式识别**：AI 识别出"漂移与 dt 无关意味着物理方程错误"这个反直觉的结论，而我最初以为是数值精度问题

**协同涌现的价值**：
最妙的时刻是 AI 修复能量漂移后，我提出"能否生成一个视频展示修复效果"。AI 立即创建了 `record_video.html`，使用 MediaRecorder API 录制 Canvas。这个需求我从未明确提过，但 AI 基于上下文推断出"修复后应该展示成果"。这种"意图的意图"理解，是人机协同的高级形态。

**最终感悟**：AI 不是替代程序员，而是将程序员从"语法工人"提升为"意图架构师"。我的角色从"写代码"转变为"定义问题、提供证据、验收结果"。这种转变让我有更多时间思考物理本质，而不是纠结于 `ctx.beginPath()` 的语法细节。

## 选做扩展：视频录制功能

除了核心的双摆仿真，我还实现了 `record_video.html` 视频录制工具：

**功能说明**：
- 使用 Canvas `captureStream()` API 捕获动画帧
- 使用 `MediaRecorder` API 录制为 WebM 视频
- 支持 10 秒自动录制，30 fps，5 Mbps 比特率
- 一键下载视频文件

**技术实现**：
```javascript
const stream = canvas.captureStream(30); // 30 fps
const mediaRecorder = new MediaRecorder(stream, {
  mimeType: 'video/webm;codecs=vp9',
  videoBitsPerSecond: 5000000
});
```

**使用场景**：
- 记录仿真实验过程，用于实验报告
- 展示混沌运动的视觉美感
- 教学演示，分享给学生
